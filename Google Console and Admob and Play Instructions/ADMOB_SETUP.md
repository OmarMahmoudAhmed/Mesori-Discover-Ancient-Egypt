# إعلانات AdMob في Mesori (بينية + مكافئة، بدون بانر)

الكود جاهز، والإعلانات **مقفولة افتراضياً** لحد ما تفعّلها بنفسك من Supabase. الدليل ده بيشرح اللي اتعمل، وإيه اللي عليك تعمله بالترتيب.

## 1) اللي اتجهّز في المشروع

| الملف | الوظيفة |
|---|---|
| `package.json` | `@capacitor-community/admob@8.2.0` (بيجيب Google Mobile Ads SDK 25.4.x + UMP) |
| `android/app/src/main/AndroidManifest.xml` | `APPLICATION_ID` من `@string/admob_app_id` + صلاحية `AD_ID` |
| `android/app/src/main/res/values/strings.xml` | `admob_app_id` = **معرّف اختبار Google حالياً** |
| `supabase/migrations/017_app_config.sql` | جدول `app_config` (Remote Config) بقيم ابتدائية آمنة |
| `src/lib/adConfig.js` | جلب الإعدادات + cache ساعة + قيم افتراضية آمنة |
| `src/lib/ads.js` | تهيئة الـ SDK، الموافقة (UMP)، الإعلان البيني، الإعلان المكافئ |
| `src/App.jsx` | `initAds()` بعد تسجيل الدخول والـ onboarding |
| `src/pages/QuizPage.jsx` | الإعلان البيني عند مغادرة شاشة النتيجة («المرحلة التالية» / «العودة للمراحل») |
| `SettingsDropdown.jsx` | زر «خيارات الإعلانات والخصوصية» (يظهر فقط لو Google قالت إنه مطلوب: أوروبا/UK) |
| `android/app/build.gradle` | تحذير وقت `bundleRelease` لو `admob_app_id` لسه معرّف الاختبار |

الإعلانات بتشتغل **على Android فقط**؛ على الويب كل الدوال no-op.

## 2) إعداد حساب AdMob

1. أنشئ حساب AdMob، وأضف تطبيق **Android** باسم الحزمة `com.omarmahmoud.mesori`.
2. هتاخد **App ID** شكله `ca-app-pub-1234567890123456~1234567890` (فيه `~`). حطه في `android/app/src/main/res/values/strings.xml` مكان معرّف الاختبار.
3. أنشئ وحدتين إعلانيتين:
   - **Interstitial** (بيني) → معرّف شكله `ca-app-pub-…/…` (فيه `/`).
   - **Rewarded** (مكافئ) → وحدد عنصر المكافأة (مثلاً `points` × 10).
4. **لا تنشئ وحدة Banner.**

> تحذير: لا تخلط بين الاتنين. App ID (`~`) في `strings.xml`، ومعرّفات الوحدات (`/`) في Supabase. ولازم الوحدات تكون تابعة لنفس الـ App ID، وإلا الإعلانات هتفشل في التحميل.

## 3) إعداد Supabase

شغّل `supabase/migrations/017_app_config.sql` (SQL Editor). بيعمل جدول `app_config` بالقيم دي:

| المفتاح | القيمة الابتدائية | الوظيفة |
|---|---|---|
| `enable_ads` | `false` | Kill Switch: `true` يشغّل، `false` يوقف الكل |
| `ads_test_mode` | `true` | `true` = إعلانات اختبار Google فقط (بيتجاهل المعرّفات الحقيقية) |
| `interstitial_ad_id` | معرّف اختبار Google | معرّف وحدتك البينية الحقيقي |
| `rewarded_ad_id` | معرّف اختبار Google | معرّف وحدتك المكافئة الحقيقي |
| `interstitial_cooldown_min` | `3` | الحد الأدنى بين إعلانين بينيين (مسموح 1–120) |

التعديل من **Dashboard ← Table Editor ← `app_config`**. التغيير بيوصل للمستخدمين خلال ساعة (مدة الـ cache).

## 4) ترتيب التفعيل (آمن)

1. **تجربة بإعلانات اختبار:** `enable_ads = true` و`ads_test_mode = true`. ابني التطبيق على جهاز حقيقي وجرّب (انظر القسم 8). المفروض تشوف إعلانات عليها علامة Test Ad.
2. **اربط الموافقة (UMP):** AdMob ← **Privacy & messaging** ← أنشئ رسالة **European regulations** (GDPR) وانشرها. بدونها إعلانات مستخدمي أوروبا/UK ممكن ما تظهرش أو تتقيّد (Google بتشترط موافقة هناك).
3. **حدّد الـ Frequency Capping** من لوحة AdMob على الوحدة البينية: 3–4 مرات يومياً لكل مستخدم (توصية الدليل الأصلي كنقطة بداية، وتتعدّل بعد قياس الاحتفاظ بالمستخدمين).
4. **الإنتاج:** بعد ما `admob_app_id` الحقيقي يبقى في الـ APK المنشور، حط المعرّفات الحقيقية في Supabase وخلّي `ads_test_mode = false`.
5. **أثناء تجربتك على جهازك** بمعرّفات حقيقية: سجّل جهازك كـ Test device في AdMob. **ممنوع تضغط على إعلاناتك الحقيقية** (ده invalid traffic وممكن يوقف الحساب).

الطوارئ: `enable_ads = false` بيوقف العرض خلال ساعة، ومن غير ما ترفع نسخة.

## 5) إزاي بتشتغل الإعلانات

- **مفيش تهيئة للـ SDK** لو `enable_ads = false`. وبتحصل بعد تسجيل الدخول والـ onboarding.
- **البيني:** مبيظهرش فور فتح التطبيق، ويحترم الفاصل `interstitial_cooldown_min` (بيتحسب من آخر إعلان أو من لحظة فتح التطبيق). بيتحمّل مسبقاً، فلو مش جاهز بيتخطّى بدل ما يخلّي المستخدم ينتظر.
- **المحتوى:** حد أقصى Teen (التطبيق 13+). ولمن هم تحت 16 بيتبعت وسم TFUA.
- **الموافقة:** لو Google قالت إنها مطلوبة بيظهر نموذج UMP، ولو المستخدم رفض مفيش إعلانات.
- كل الدوال **لا ترمي أخطاء**: فشل الإعلان ما بيكسرش التطبيق. ومفيش أي تسجيل لمعرّفات أو بيانات.

## 6) الإعلان المكافئ (جاهز، بدون واجهة)

```js
import { showRewardedAd } from '../lib/ads';

const handleWatchAd = async () => {
  const res = await showRewardedAd();
  if (res.rewarded) {
    // res.amount / res.type جايين من إعداد الوحدة في AdMob
    grantReward(res.amount);
  } else {
    // res.reason: 'dismissed' | 'load-failed' | 'disabled' | 'no-ad-unit' | 'not-ready' | 'busy' | ...
  }
};
```

- ما اتربطش بأي زر لأن المكافأة قرار منتج (إيه اللي هيكسبه المستخدم؟). اربطه بزر اختياري واضح.
- **مهم:** المكافأة بتتحقق من العميل، يعني ممكن تتزوّر. لو هتديها نقاط بتأثر على الليدربورد، استخدم **Server-Side Verification** (خيار `ssv` في `prepareRewardVideoAd` + callback من AdMob لـ Edge Function) وما تضيفش النقاط من العميل.
- الـ promise الأصلي `showRewardVideoAd()` **مبيتحلّش** لو المستخدم قفل الإعلان قبل المكافأة؛ عشان كده الكود بيعتمد على الأحداث (ومعاه مهلة أمان 5 دقايق).

## 7) نقاط مهمة

- **الـ SDK في وضع الصيانة:** Google بتوجّه المطورين لـ GMA Next-Gen SDK. الـ plugin الحالي على الـ SDK 25.x (حالته «Supported»، وتاريخ الـ deprecation 30 يونيو 2027 والـ sunset 30 يونيو 2028 حسب صفحة Google الرسمية وقت كتابة الدليل). متابعة: لما الـ plugin يدعم Next-Gen، رقّي. راجع https://developers.google.com/admob/android/deprecation
- **Data safety + سياسة الخصوصية:** اتحدّثوا (`data-safety-answers.md` و`privacy-policy.html`). لازم تحدّث نموذج Play Console بنفس الإجابات **قبل** نشر أول نسخة فيها الـ SDK، حتى لو الإعلانات مقفولة.
- **تعارض في الوثائق:** `App Marketing.md` بيقول «لا إعلانات بينية وإعلانات مكافأة فقط». ده بيتعارض مع الدليل ده. حدّد القرار وحدّث الملف.
- تطبيق 13+ غير موجّه للأطفال: لو Google اعتبرته موجّه للأطفال هتطبّق Families Policy والإعلانات هتتغيّر.

## 8) اختبار على جهاز حقيقي (لم يُنفَّذ آلياً)

1. `enable_ads=true`, `ads_test_mode=true` ← افتح التطبيق وأكمل مرحلة: **مفيش إعلان قبل مرور فاصل الـ cooldown من فتح التطبيق**.
2. بعد الفاصل: أنهِ مرحلة واضغط «المرحلة التالية»: يظهر إعلان اختبار بيني. ثاني مرة فوراً: لا يظهر.
3. `enable_ads=false` ← بعد ساعة (أو امسح بيانات التطبيق) لا تظهر إعلانات.
4. وضع الطيران: التطبيق شغّال عادي ومفيش إعلانات ولا أخطاء.
5. أوروبا (اختياري): غيّر منطقة الجهاز/VPN وتأكد من ظهور نموذج الموافقة وزر «خيارات الإعلانات والخصوصية».
6. فحص الـ merged manifest بعد `bundleRelease`: فيه `APPLICATION_ID` و`AD_ID`.

## 9) اختلافات عن الدليل الأصلي (ولماذا)

| الدليل الأصلي | هنا | السبب |
|---|---|---|
| `initializeForTesting: true` ثابت | الوضع من `ads_test_mode` (Supabase)، وبمعرّفات Google | الـ flag ده وحده مبيخلّيش الإعلانات اختبارية، وثابت في الكود هيفضل في الإنتاج |
| Fallback = تفعيل الإعلانات بمعرّفات اختبار | Fallback = **إعلانات مقفولة** | لو الشبكة فشلت في الإنتاج ما يظهرش «Test Ad» للمستخدمين |
| قراءة `app_config` لأي حد (حتى غير المسجّل) | `authenticated` فقط + عمود `is_public` | التطبيق بالكامل بعد تسجيل دخول (نفس أسلوب migration 016) |
| `prepare` ثم `show` وقت الطلب | تحميل مسبق، والتخطّي لو غير جاهز | عدم تأخير المستخدم |
| لا فاصل بعد فتح التطبيق | الفاصل يُحسب من فتح التطبيق | توصية الدليل نفسها: لا إعلان فور الفتح |
| `alert()` عند المكافأة وعدّاد نقاط تجريبي | الدالة بترجع النتيجة بس | القرار المنتجي يتحدد في الواجهة |
| TypeScript + React Hook | JavaScript + module | المشروع JS، والاستدعاء من أحداث مش من render |
| — | إضافة: UMP، حد المحتوى Teen، TFUA، فحص Kill Switch عند كل عرض، مهلة أمان، `AD_ID` | امتثال Google Play/GDPR |
